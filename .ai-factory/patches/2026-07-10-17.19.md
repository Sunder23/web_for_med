# Nav sub-menu rendered flat — no dropdown on desktop, no accordion on mobile

**Date:** 2026-07-10 17:19
**Files:** theme/vite-wordpress-starter-theme/assets/src/scss/layout/_header.scss, theme/vite-wordpress-starter-theme/assets/src/js/components/mobileNav.js
**Severity:** medium

## Problem

The main menu's "Послуги" item has four child items (`.sub-menu`). On desktop
the children rendered inline inside the header's flex row (breaking the layout
whenever a submenu exists), and in the mobile overlay they appeared as flat
full-size (24px) items indistinguishable from top-level links.

## Root Cause

The theme's nav styles and `mobileNav.js` were written against a flat menu.
WordPress's `wp_nav_menu()` emits `.menu-item-has-children` on parents and a
nested `ul.sub-menu`, but nothing in `_header.scss` targeted those classes, so
nested `<li>`s inherited the top-level flex/typography rules. The gap existed
in both duplicated menus (`menu-main-desktop` and `menu-main-mobile`) because
the layout was originally built before any menu item had children.

## Solution

- **Desktop** (`.nav--desktop .menu-item-has-children`): CSS-only dropdown —
  absolutely positioned bordered panel (`top: calc(100% + 14px)`, centered via
  `left: 50%` + translate), toggled by `:hover` **and** `:focus-within` for
  keyboard access. A `::before` pseudo on `.sub-menu` spans the 14px gap as an
  invisible hover bridge (it's a child of the `<li>`, so hovering it keeps
  `li:hover` true), plus a delayed `visibility` transition for forgiveness.
  Caret drawn with a rotated border chevron on the parent link's `::after`.
- **Mobile** (`.nav--mobile-overlay`): parents link to real pages, so
  navigation stays on the `<a>` and expand/collapse lives on a separate
  `.sub-toggle` button injected by `mobileNav.js` next to the parent link.
  Toggling flips `.is-sub-open` on the `<li>` (max-height + opacity
  transition) and `aria-expanded` on the button; `closeNav()` resets all open
  submenus. `.nav__links` got `overflow-y: auto` so expanded submenus can't
  overflow short viewports. `[FIX]` logging via the `logDebug` util.

Verified live via Chrome DevTools (desktop hover + 375x812 mobile emulation).

## Prevention

- When styling `wp_nav_menu()` output, always account for WordPress's nested
  markup (`.menu-item-has-children`, `.sub-menu`, `current-menu-*` classes)
  even if the current menu is flat — editors can add children at any time.
- When a dropdown parent is itself a link to a real page, don't hijack its
  click for expand/collapse on mobile — inject a dedicated toggle button so
  navigation and disclosure stay separate (and keep `aria-expanded` on the
  button, not the link).
- For hover dropdowns separated from their trigger by a gap, add a
  pointer-transparent bridge pseudo-element inside the hoverable ancestor;
  otherwise the dropdown closes when the cursor crosses the gap.
- Remember the theme renders the menu twice (desktop nav + mobile overlay):
  scope dropdown styles per variant and inject JS behavior only into
  `#mainNav`, or desktop gets dead toggle buttons.
